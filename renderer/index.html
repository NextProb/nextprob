Server Sync (SFTP)

Sync workspace files between your local workspace and remote OpenClaw servers via SSH/SFTP. No server-side setup needed — any server with SSH access works.

How does it work?

Automatic two-way sync — changed files are pushed to the server after a short delay. A full sync runs every 5 minutes to pull new or modified files from the server.

Conflict handling — if the same file is edited on both sides, the server version is saved as filename.conflict.{timestamp}.html and a yellow banner appears so you can choose which version to keep.

First sync — files that exist only on one side are copied to the other. Files that exist on both sides with different content create a conflict so you can review them.

What gets synced — all workspace files except those matching patterns in .syncignore (uses .gitignore syntax). Default exclusions: .git/, .notes-app/, node_modules/.

SSH Agent on macOS — if the app is launched from Finder, SSH_AUTH_SOCK may not be set. If the agent method fails, try specifying a key path instead, or launch the app from the terminal.

Use wss:// when your server has TLS (HTTPS). Use ws:// for local or tunneled connections.

Only needed if your OpenClaw server has OPENCLAW_GATEWAY_TOKEN configured.

How to find it:

  1. SSH into your server
  2. Open ~/.openclaw/openclaw.json
  3. Copy the value at gateway.auth.token

If using Docker, check the OPENCLAW_GATEWAY_TOKEN environment variable in your docker-compose.yml or .env file.

If your server doesn't require a gateway token, leave this blank.
